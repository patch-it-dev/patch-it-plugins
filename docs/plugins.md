# Supported plugins

Every source patch-it watches is one plugin. This is the list of them: **if a plugin isn't here, it doesn't exist yet**. Add a row when you add a plugin, and update it when you change one (see [AGENTS.md](../AGENTS.md)).

Each plugin's id links to its provider page in [`providers/`](../providers/): why that source, what the plugin reads and ignores, and its known gaps. How to add one: [writing-a-plugin.md](writing-a-plugin.md).

The table between the `plugins:start` and `plugins:end` markers is also published on [docs.patch-it.dev](https://docs.patch-it.dev/supported-apis/plugins/): the docs site reads this file from `main` when it builds. Keep it a plain Markdown table, one row per plugin, with absolute links only. [`plugins.json`](plugins.json) is the same list as JSON (id, provider, layer, format, source URL, status, provider page; schema in [`plugins.schema.json`](plugins.schema.json)), generated by `make plugins-json`.

## The columns

| Column | Meaning |
|---|---|
| Plugin | The id you pass as `--api` and the `api` field on every event it emits. Lowercase, unique. |
| Provider | Whose API, SDK or package it is. |
| Layer | Which kind of dependency it covers: `API`, `SDK`, `package`, `runtime`, `CI` or `AI models`. |
| What it watches | The kind of change it reports, in a few words. |
| Format plugin | Which shared reader it is built on: `openapi` (a spec per release, diffed), `retirements` (a deprecations page), `migrationguide` (an SDK's migration guide), `removedmembers` (a package's table of removed members, in RST or Markdown), `changelog` (a release changelog file), `feed` (an RSS or Atom feed), `catalog` (a structured JSON catalog of names, diffed between two snapshots), `apichangelog` (a vendor's machine-readable API changelog, in JSON). |
| Source | The provider's own public page or file the plugin reads. Every event links back to it. |
| Status | `live`: in the code on `main`. patch-it's hosted ingestion service runs it daily from the next release, which is cut automatically. `planned`: accepted, not written yet. `paused`: in the code but deliberately switched off, with the reason in the row. |

Some plugins read one pinned release (`anthropic` 1.0.0, `newrelic` 11.0.0, `numpy` 2.0.0, `posthog` 8.0.0, `textual` 0.86.0, `urllib3` 2.0.0): a newer release of the same package is a new entry in that plugin, not a new row, unless it changes the format.
